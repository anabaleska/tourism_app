# Чекор 4 — GitHub Actions CI и објавување имиџи

Workflow: `.github/workflows/docker-publish.yml`.

При push на main се извршува test job: проверка на Compose конфигурацијата, градење и стартување на трите сервиси во нова CI база, чекање на healthcheck-овите и проверка на HTTP endpoints. Се проверуваат login страницата и JSON одговорите на FastAPI root и двата recommendation endpoints за непостоечки идентификатори. Ова е проверка на интеграцијата и на празна база, не целосен тест на алгоритмите, регистрацијата или сите функционалности. Flyway миграциите мора да успеат за backend да стане healthy. Имиџите не се објавуваат ако test job не помине.

Publish job ги гради и објавува двата имиџа во Docker Hub:

- `blazheskamarijaa/tourism-backend:latest`
- `blazheskamarijaa/tourism-recommendations:latest`
- Секој имиџ добива и `sha-<целосен Git commit SHA>` tag за идентификација на верзијата.

При pull request се извршува само проверката. Рачно стартување е достапно преку workflow_dispatch; објавување е дозволено само од main. Потребни GitHub Actions repository secrets: DOCKERHUB_USERNAME и DOCKERHUB_TOKEN. Токенот треба да има право за запишување во Docker Hub репозиториумите; не се зачувува во изворниот код.

Cleanup со `docker compose down --volumes` се извршува само во привремената GitHub Actions околина, за нејзината тест-база. Не се користи за локалната база со податоците.

## Статус

Workflow-от е подготвен локално. Успешно CI извршување и објавување сè уште не се потврдени. Потребни се Docker Hub репозиториуми, GitHub secrets и push на main. Овој workflow нема автоматско поставување на сервер (CD).

## Докази за елаборатот

По успешен run: слика од зелени test и publish jobs; слика од Docker Hub tags за двата имиџа; извадок од workflow конфигурацијата. Завршеното објавување се опишува во елаборатот откако ќе се потврди.
